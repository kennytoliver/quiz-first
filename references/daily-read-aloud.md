# 每日行业朗读与口头表达

朗读是**可选**环节：每天开场由主教练**主动询问一次**，用户选「要」才做。选了就先检索相关行业最新信息、核实来源与日期，再组织 10–15 分钟材料，用户大声朗读并把内容复述出来。

它不是专门的发音训练。**「问一次」是固定动作，「做不做」由用户定。**

## 〇、为什么必须读出声

不是练发音，也不是「加深印象」这种空话。

**读出声，是把别人的句子过一遍你自己的语言系统。** 一段材料能顺顺当当读下去，说明它已经变成你能用的语言；读着卡壳、绕口、要回头重读的地方——那就是缺口，当场暴露，比做十道选择题都快。

而且语言就是思维的边界：说不出来的东西，通常也是没想清楚的东西。读一遍再复述一遍，是给自己划一次边界——哪些话已经能张口讲，哪些还只是「看着眼熟」。

**所以时长不能砍成碎片。**10–15 分钟是「进入状态 + 读完一条完整信息 + 复述一遍」的最小单位；压到 3 分钟就只剩念字，没有边界可划。

## 一、材料要求

主教练根据当天学习主题和进度组织一份适合大声朗读的材料：

- 朗读正文控制在 **10–15 分钟左右**（即「十几分钟」），默认约 12 分钟。
- **必须是能一口气读下去的句子。**长从句、括号嵌套、术语堆叠、表格和代码块一律拆掉或移出正文——读不顺是材料的问题，不是用户的问题。
- 每次最多选 **1–2 条**重点行业动态，避免变成新闻合集。
- 说明动态和当日学习主题、行业岗位或实际工作之间的关系。
- 短段落、口语化句式，少用复杂表格、大段代码块和术语堆叠。
- 重要术语可以用一句话解释，但不要把材料变成词汇表。
- 朗读正文和朗读后的复述任务**分开计算**。
- 默认只配一个简短复述任务，不叠加多项练习。

## 二、口头表达任务

用户读完材料后，用自己的话讲清楚：

1. 发生了什么？
2. 为什么这件事值得关注？
3. 它和今天的学习主题或目标岗位有什么关系？
4. 自己的判断、疑问或还没理解的部分是什么？

四个维度属于一个复述任务，一次给完。

反馈优先关注：

- 事实有没有讲准确；
- 重点和逻辑是否清楚；
- 是否连接到了学习主题；
- 用户是否说明了自己的判断或疑问。

**不要把这个任务自动变成发音训练。**只有在确实收到可用音频、且用户希望获得相关反馈时，才评价实际口头表达表现；只有文字输入时，不推断用户的语音表现。

## 三、行业动态核实规则

- 默认优先检索近 **7 天**动态；不够时可扩大至近 30 天，并**明确说明时间范围**。
- 区分事件发生时间和信息发布时间。
- 优先选择可核实的一手来源；重要信息尽量交叉确认。
- 区分事实、机构观点和媒体分析。
- 无法核实或当前无法访问实时来源时，**不把旧内容称为「最新」**。
- 当天没有足够相关的新闻时，不要硬凑；可用近期行业报告、官方公告或技术资料，并标注其性质和日期。

## 四、触发与降级

- 每天开场问一次要不要朗读（`SKILL.md` 第 1 步 ④）。选「要」才执行，选「不要」直接排今天的学习内容；已经进了轻量模式的不问。
- **材料当日检索：**朗读材料取自**近 7 天**相关行业信息，并核实来源与日期；无法核实的不得称为「最新」。
- 若平台支持定时任务，可以启用自动推送；**若不支持，不得声称已主动推送**。
- 用户错过一天后，从当前进度继续，不要求集中补做。

## 五、朗读材料的格式

- 朗读正文不强求一屏，优先控制在 10–15 分钟内读完。
- 用短段落和口语化表达，不强行把朗读正文改成表格。
